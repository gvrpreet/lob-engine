# Experiment: Dense price levels            Date: 2026-09-26      Commit: baseline d07611a + working tree
**Hypothesis:** For the synthetic workload, most resting prices are near a central market price. A dense array with an occupancy bitmap over that band should reduce per-level tree work; an ordered overflow map should preserve semantics for arbitrary out-of-band `Price` values.
**Change:** Introduced a level-store policy with `TreePriceLevels` as the unchanged default and an opt-in `DensePriceLevels` backend. The dense backend covers ticks 9,000 through 11,000 inclusive, uses a bitmap to track occupied slots, and stores prices outside the band in an ordered map. Matching, cancellation, best-price queries, level counts, and checksums use the shared interface. Added `replay_dense` and a benchmark case; no default backend was changed.
**Method:** Compared tree and dense stores in the same Release-preset `bench_match` process: GCC 13.3, `RelWithDebInfo`, `LOB_NATIVE=ON`, 1M generated events (seed 42), CPU affinity core 2, seven alternating runs per invocation, three invocations. Host: AMD Ryzen 7 7840HS, Ubuntu 24.04 under WSL2 kernel `6.18.33.2-microsoft-standard-WSL2`; governor not exposed. Hardware `perf` counters are unavailable. Correctness was checked with a 100k-operation dense-band differential seed, a replay-equivalence case, and explicit lower/upper/extreme overflow-price cases.
**Results:** All six benchmark variants produced checksum `ba7911b3a1dd1d8a`. Across the three invocations, tree-store medians were 29.70-30.91M events/s; dense-store medians were 32.15-34.56M events/s. The aggregate per-invocation min/max ranges overlap substantially: tree 24.07-32.73M, dense 26.55-38.23M events/s. Dense appears faster by median in these samples, but the overlap and environment noise do not establish a reliable winner. Dense-specific latency percentiles and hardware counters were not collected.
**Explanation:** The synthetic workload fits mostly inside the central band, and the dense backend preserves the same replay state. The bitmap removes tree-node lookup for in-band prices, but best-price discovery scans bitmap words and the experiment has no hardware counter evidence to explain the throughput delta. This is an opt-in comparison, not justification to replace `std::map` as the default.
**Surprises / next questions:** How does a summary bitmap affect best-price discovery? What happens with deeper books, wider price offsets, or sparse levels? How often does a realistic market enter the overflow map? Re-run on native Linux with branch/cache counters before considering a default change. Compare a sorted vector only after establishing representative depth and density.
