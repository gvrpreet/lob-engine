# Experiment: Sorted-vector price levels            Date: 2026-09-26      Commit: baseline 5afd856 + working tree
**Hypothesis:** For shallow books (about 10-50 active levels), a sorted vector with the best level at the back may outperform both the tree and dense bitmap by improving locality and avoiding node allocations.
**Change:** Added `SortedPriceLevels<Compare>` as an opt-in level-store policy. Levels are stored in worst-to-best order so the best is at the back for both sides; binary search handles lookup and insertion/erase shift vector entries. Added a separate book/replay path and benchmark case. The default remains tree-backed.
**Method:** `bench_match` compared all seven variants on 1M generated events (seed 42), GCC 13.3, Release preset (`RelWithDebInfo`, `LOB_NATIVE=ON`), CPU affinity core 2, seven alternating runs per invocation, three invocations. Host: AMD Ryzen 7 7840HS, Ubuntu 24.04 under WSL2 kernel `6.18.33.2-microsoft-standard-WSL2`; governor and hardware counters were unavailable. Tree, dense, and sorted variants used the same flat ID index, order pool, events, warm-up, and checksum check. Sorted backend correctness was checked with a 100k-operation differential seed, a replay equivalence run, and direct bid/ask ordering, cancel, and fill tests.
**Results:** Checksums matched across all variants (`ba7911b3a1dd1d8a`). Across the three invocations, tree-store medians were 22.62-23.06M events/s, dense-store medians 23.43-24.31M, and sorted-vector medians 21.63-21.83M. Aggregate min/max ranges overlap: tree 19.69-24.83M, dense 22.23-26.51M, sorted 18.50-23.41M events/s. The sorted vector did not improve throughput in this synthetic workload; no backend default changed. Hardware counters and a workload explicitly constrained to 10-50 active levels were not available in this run.
**Explanation:** Binary search makes lookup logarithmic, but insertion and erase move vector elements; that mutation cost appears to outweigh locality benefits here. The current benchmark's actual active-level count is not reported, so this does not conclusively reject sorted vectors for deliberately shallow books. WSL2 provides no counter evidence to explain the observed difference.
**Surprises / next questions:** Add explicit active-level-depth reporting or construct controlled 10-, 25-, and 50-level workloads before rejecting this layout for shallow books. Revisit on native Linux with branch/cache counters. Keep it experimental and preserve the tree default.
**Phase 4 follow-up (2026-09-26):** A later opt-in shape pass over the same generated seed-42 1M event stream found 133 final and 135 peak total active levels. Thus this earlier comparison did not exercise the intended 10-50-level shallow-book case; use controlled-depth inputs before drawing conclusions about sorted vectors.
