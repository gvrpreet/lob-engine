# Experiment: Active-level shape telemetry            Date: 2026-09-26      Commit: baseline 435c1aa + working tree
**Hypothesis:** Reporting final and peak active price-level counts alongside throughput will expose whether a synthetic workload actually represents the 10-50-level regime used to motivate the sorted-vector experiment.
**Change:** Added opt-in `ReplayConfig::measure_book_shape` metrics for final/peak total active levels. Normal replay leaves the metrics zero and does not perform per-event level counting. `bench_match` runs a separate untimed shape pass and prints those counts with the checksum before timed results.
**Method:** Used `bench_match` with seed 42 and generated 100k and 1M event streams. Compared metric values across tree, dense, and sorted backends in tests; no profile counters or throughput comparisons were inferred from the shape pass.
**Results:** The 100k stream ended at 67 levels and peaked at 67. The standard 1M stream ended at 133 and peaked at 135. The metric test confirms default stats stay zero when disabled and enabled values match across tree, dense, and sorted backends. Full ASan/UBSan and Release checks pass (37 tests).
**Explanation:** The prior 1M sorted-vector comparison was not a 10-50-active-level workload, so it cannot settle the shallow-book hypothesis. The new separate pass avoids adding depth-counting work to timed benchmark cases.
**Surprises / next questions:** The standard 1M stream had 135 peak levels, not the expected shallow depth. Controlled 10/25/50 add/cancel and trade-enabled streams now verify exact depth; see the two controlled-depth notes. Next, profile on native Linux or vary trade rate/order size.
